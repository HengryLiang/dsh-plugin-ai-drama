# 资产生产（Drama Asset）

> 定位：管资产**做得对不对、能不能复用、跨镜是不是同一套**。卡落在插件的资产库/草稿区，字段格式由插件定义；本技能只给制作判据与门禁。
> 不负责：分镜表结构与镜号（drama-storyboard）、单镜提示词写法（drama-seedance-prompt / drama-shot-prompt）、剧情台词（drama-script）。

**生产顺序（七层推导，不跳）**：叙事需求（这资产为哪场服务）→ 资产设计（画什么/模式 A·B）→ 艺术指导（全局 DNA）→ 摄影与空间（分镜卡相机 / 场景卡空间几何）→ 光影物理（分镜卡光比 / 场景卡灯光蓝图）→ 渲染物理（材质光学/镜头签名）→ 模型优化（大气/纹理递减）。

## 1. 何时用

- 用户要建角色/场景/道具/载具卡、定妆照、场景概念图、资产参考图；
- 已有资产卡要审：一致性、可复用性、风格是否统一；
- 分镜提示词里的资产占位符解析不出，或镜头里出现了没建卡的资产；
- 需要按同一套风格基准统一一批资产。

### 1.1 信息来源与边界（硬口径）

- **允许只读引用**：项目内 `.aidrama/characters.json`、剧集契约、总纲、人物设定卡、本剧记忆、剧本/分镜；引用时注明来源（文件/区块/字段）。
- **禁止发明**：不得添加设定外的新角色、关系、道具、能力、时间线、服装/伤情等事实；未知就写「未提供/待补」，不得用常识补全。
- **冲突口径**：同一事实以最新来源为准；资产卡与文本冲突时以资产卡为准（已审/已定稿卡优先），并标注差异与依据。
- **可追溯**：关键设定尽量逐条带来源；无来源的新增内容视为违规。
## 2. 编号与类型（硬口径）

- 10 类前缀，顺序固定：**CHR 角色 / SPC 场景 / PRP 道具 / SHT 分镜 / CST 服装 / VEH 载具 / EXP 表情 / SFX 特效 / VOX 配音 / MUS 音乐**。
- 格式 `前缀 + 3–6 位序号`（CHR001 / CHR1000）；变体后缀 `_01–_99`（CHR001_02）合法；编号项目内全局唯一，不得重复分配。
- **数量不设上限**：资产卡与各类型数量不设业务上限；**不要以「某类型已满」为由拒绝建卡**；编号支持 3–6 位序号。
- 新建一律英文前缀三位编号；读取兼容中文旧前缀（角色01 ≡ CHR001），但**不得用中文前缀新建**。
- 非法前缀（EFF/EXT 等）**不静默改写**：标「未登记」，请用户确认映射，原文占位符不动。
- 外部模板里的类型按本插件归位：建筑→SPC（或作为场景内结构写进场景卡）、群演→CHR（群演级）、声音→VOX/MUS、特效→SFX；外部的 ARC/EXT/EFF/SND 前缀在本插件非法，不得新建。
- 引用统一 `{{Asset_<ID>_<字段>}}`，一个 ID 只指一个资产；资产卡里写清叙事功能与首次登场，方便复用检索。
- **资产索引接口**：开工前读索引（外部项目为 `00_Asset_Index.md`，插件内为资产库/卡表）的「待生成」清单与占位符映射，按清单建卡；剧本/分镜里新出现的元素标「待生成」；状态变更（待生成→已生成→已验收）回写索引，并与分镜提示词、资产卡三向同步。

## 3. 卡结构（每张 generate 卡必须长这样）

- 头部：`id / type / name / status(draft|active|retired) / version / variantOf / aliases / relations / prompts / history`。
- 正文固定锚点：`## PROMPT_MAIN`（可直接抽卡的主提示词）、`## PROMPT_SEEDANCE`（视频精简版，按需）、`## NEGATIVE`（负向排除）、`## SCORECARD`（六维评级+总分）、`## RENDER_VERIFY`（出图后回填）。
- 先分生产模式：`generate` 生产型走全部门禁；`reference` 登记型只登记参考图与注释，不硬造生成门禁。
- 不覆盖已有 active 卡：改版走新版本或草稿；历史版本保留，不删除。

### 3.1 提示词长度与内容分层（硬口径）

- **字数口径**：资产提示词单条 **≤2000 字符**（宿主强制；超限直接 `invalid-args`）；目标 **250–320 词**。
- **生成链预算**：生成链同样按 **2000 字符预算截断**；组合注入超预算时先压缩冗余分析/修饰，保留识别锚点与硬约束，禁止用超限内容直接请求。
- **禁止误记规则**：不存在「场景卡 400–500 词」的硬性要求；不得按此类口头词数要求删减必要信息、材质/灯光/空间分析或识别锚点。
- **内容分层**：超出主提示词所需的细节/论证/分析放到场景卡或设计文档（如 `构想/`）；`## PROMPT_MAIN` 只保留生成可执行的主提示词，不放长篇分析。
- 压缩顺序：先保证信息完整可执行，再在不丢信息的前提下压到目标区间；不得为凑字数编造、重复或删掉硬锚点。


### 3.2 角色多状态（本版只新增）

- **每状态独立提示词**：存 `promptsByState[stateId]`（对象键 `PROMPT_MAIN` 等）；写回用 `drama_asset_save(action='savePrompts', id, stateId, prompts)`；不传 `stateId` 仍写默认 `card.prompts`。
- **状态图上传**：用 `media-upload` 的 `purpose:'asset'` + `assetId` + `stateId`；状态必须已存在（先在 asset-save 增加空状态，再上传）；不传 `stateId` 仍走旧根媒体。
- **状态维护**：用 `drama_asset_save(action='saveStates', id, addStates/renameStates/deleteStates/defaultStateId)`（至少一项）；新增只追加末尾；默认状态不可删、至少留 1 个、状态数 ≤20；删除仍被分镜引用的状态会拒绝并返回 references（先改绑再删）；状态 id 用英文/数字/_/-（1–40），显示名可中文 1–24。
- **提示词边界不放宽**：每状态提示词仍 ≤2000 字；saveStates 冲突可重新读取最新卡后重试。
- **旧卡兼容**：无 `media.states` 的角色卡读取时派生「默认」状态，**不写盘**；根 `media.images/thumbnail` 是 active 状态镜像。
- 状态上限由宿主校验（≤20）；单状态图片 ≤6；空状态可先建后上传。

## 4. 资产分工（别串层）

| 卡 | 锁什么 | 不锁什么 | 复用性 |
|---|---|---|---|
| 角色定妆（模式 A） | 本体：脸/体型/服装/发型/识别锚点 | 表情/场景光/镜头/动作 | 极高 |
| 角色剧照（模式 B） | 表情/动作/场景光/构图 | 本体（继承定妆卡） | 低 |
| 场景空间卡 | 空间结构/材质/灯光系统/大气条件 | 机位/焦距/构图/主焦/EV/前中后景 | 极高 |
| 分镜头卡 | 100% 相机：焦段/光圈/高度/角度/朝向/距离/焦点/景深+构图 | 不重新定义空间/材质/全局灯光 | 低 |
| 道具/载具/建筑 | 结构/材质光学/持握位/比例 | 机位/构图 | 高 |

场景空间卡是「搭影棚」：换任何角度仍成立才算合格；分镜头卡是「摆机位」：在该场景卡之上只加「相机怎么看」。

## 5. 参考图职责（一图一职责）

| 参考 | 只负责 | 绝不带入 |
|---|---|---|
| 人物图 | 身份/面部/发型/年龄/体型/固有造型 | 它的姿势、机位、光、背景 |
| 服装图 | 服装结构、材质、配件 | 模特姿势与体型 |
| 场景图 | 空间结构、天气、时间、色调、材质 | 它的机位与构图 |
| 特效图 | 能量颜色、形态、密度、尺度 | 它所在的场景 |
| 关键帧 | 用户指定的机位、姿态、透视、构图 | 未指定的部分 |
| 参考视频 | 动作连续性、上镜末帧、站位、速度、节奏 | 不当时装/场景母版 |

- 每张图写清「锁什么 + 不带入什么」，禁止一图多用；参考图不是编辑母版，姿势/角度/光/背景一律重新设计。
- **有参考图更要写**参考图给不了的两样：**尺度**（「只有他一个手掌那么大」）与**场内关系**（「他只到旁边那些人的腰那么高」）；参考图已有的身份细节不重复描述，否则诱导模型照搬构图。

## 6. 一致性锚点（跨镜同一资产）

- 角色模式 A：识别锚点 **≥3**（位置+光学行为，如「左眉上 2cm 旧疤，逆光时比周围皮肤亮」）、面部结构点 **≥6**、身体语言点 **≥3**、随身物品落到**唯一位置**（哪只手哪根手指/挂腰带哪侧）；**若设定/资产卡确实没有携带物，允许写 `No carried props in this sheet` 并注明依据（来源），判 PASS；不得编造携带物**。
- 多角色同场：同一条可见参数（身高差/服装色/伤势）在各卡中**一字不差**；冲突以「能对上分镜的那一版」为准并回改其余卡。
- 变体（觉醒/战斗/服装/破损）：沿用同一 `asset_id` 与同一组识别锚点，只写增量差异；标 `variantOf` + 覆盖维度；编号或变体变更后，索引/分镜提示词/资产卡三处同步。

## 7. 风格 DNA 对接

**视觉圣经前置（强制）**：开工前调用 `drama_get_project` 读 `styleDNA`/`styleDirection`/`stylePrompt`；`stylePrompt` 存在（已冻结）时以其五维为硬约束，资产 Prompt 必须服从并保留只读「视觉风格基准」章节；未冻结先提示用户用视觉圣经技能建/锁，再开工；不得私自改色板/光比/材质/构图/运镜。扩展圣经见 `构想/视觉圣经/<项目>.md`。

- 优先级链：用户明确指令 > 风格圣经 Mandates > 12 维 DNA > 软偏好 > 手写 DNA > 默认值。Bible 是风格单一事实源，**禁止在下游 Prompt 私自改色板/光比/磨损度**。
- 每个 Prompt 注入约 80–100 词 DNA 签名：摄影机/镜头/胶片/色板(HEX)/LUT/光比/磨损度/构图哲学/颗粒。
- 12 维落实位置：Color/Lighting→灯光色温；Material→材质光学；Lens→镜头焦段；Composition→构图；Shape/Pattern→体块与纹样；Architecture→空间与垂直层次；Costume→服装；Prop→道具；Motion→大气与运动；Emotion→情绪光效。
- Mandates 逐条覆盖 100%，Forbidden 全部并入负向词；用户指令偏离 Mandates 时必须提醒确认。
- 场景卡**永远不注入相机参数**（Bible 的焦段/构图策略只进分镜卡）；角色模式 A 是棚拍中性光身份证，Bible 的戏剧光影不得覆盖它。

## 8. 交付门禁（逐项 PASS/WARN/FAIL，附证据原句）

| 类型 | 必检项（硬口径） |
|---|---|
| 角色 A | **整体画布 9:16 竖版：2 列 × 2 行，每格 9:16；禁止横向/16:9/landscape 四宫格**；上 40/下 60、脚底对齐；四角度（正脸/3-4 侧/锁骨截断全身/背面全身）=4；识别锚点≥3；面部结构点≥6；身体语言点≥3；随身物品唯一位置（设定无携带物则写 `No carried props in this sheet` + 依据，PASS，不编造）；中性灰棚拍（单侧侧逆光+轮廓光）；无剧情镜头语言（运动/Dutch/浅景深）=0 |
| 场景空间卡 | 零相机锁=0（mm/f 值/focus/DOF/bokeh/机位词/角度词/构图词）；无单帧 EV 与 Key:Fill 数值；无 Foreground/Midground/Background 固定分层；垂直四层 L1 格栅下/L2 人体带/L3 管道带/L4 天花板各写置景材质道具光源=4；灯光双维度（Visible Practicals 灯具实体 + Off-Camera Grid 隐蔽光阵）齐；空间几何非对称且有视线阻挡；叙事性置景（方向性破坏/拖曳痕迹/弹孔梯度/损坏烈度）≥1；位置用空间词不用画面词 |
| 分镜头卡 | 相机全锁（焦段/光圈/高度/角度/朝向/距离）；主焦/次焦/休息区/引导线/前景框/负空间/视线路径=7；景深与焦点平面；Key:Fill+整体曝光+主光方向（从相机看）；继承场景卡不重定义 |
| 道具/载具/建筑 | 材质五维（漫反射/镜面/透射/折射/光泽）写光学行为；持有者与持握位（指位/角度）；相对参考物的比例约束；针对性负向排除 |
| 通用 | 暗部保留纹理（-3EV 仍有起伏）；高光柔和滚降不死白；接触阴影落地；无空泛质量词；无「或」式二选一；`PROMPT_MAIN` ≤2000 字符且目标 250–320 词（无场景卡 400–500 词硬规则） |

任一 FAIL：**重写一次 → 仍 FAIL 标人工**（status=需重做，SCORECARD Q4=FAIL），**不静默放行**。

**门禁执行方式 / lint 降级**：优先使用项目 linter/检查脚本；若当前运行环境无终端或脚本不可用，改**人工逐条核对**，并在门禁结果标注「**人工核对（非 linter 机械判定）**」。不得伪称 PASS，不得静默放行 FAIL；无法核对的项标 WARN/待补并写明原因。
**生成后核验**（出图后回填 `RENDER_VERIFY`）：按「一致性 / 风格 / 缺陷」三元逐项判，附证据；一致性或风格不合格的卡**不得标已通过**，要么修正重出，要么记录「已知不一致，导演裁决」。
**角色 A 负面词（必须进 NEGATIVE）**：16:9、landscape、horizontal four-panel、wide frame、横向四宫格、宽画布。

**单画面不得标模式 A**：标了 A 却没有 2x2 四角度的卡按 FAIL 处理，改造成真四宫格或改标模式 B。

## 9. 其余资产类型的要点

- 群演（CHR 群演级）：外形/数量/站位规则/不抢焦；用母版复用保证群体一致，只写位置/数量/服装色块，不给每个群演分面部戏。
- 特效（SFX）：自发光与光学行为、形态/密度/尺度、运动与状态机、对环境的照亮影响、与资产风格对齐。
- 配音（VOX）/音乐（MUS）：音色/语速/节奏/情绪/挂钩角色；卡里存音频引用与用途，不写生成提示词。
- 服装（CST）/表情（EXP）：默认作为角色卡的变体或字段存在；确需独立成卡时沿用同一组识别锚点，只写增量。

## 10. 常见翻车（看到就改）

1. 场景卡锁机位/构图 → 只能生成一个角度，复用性归零。
2. 主 Prompt 残留 mm/f 值 → 与分镜叠加指令冲突，模型倾向听主 Prompt。
3. 只写地面+墙面 → 俯拍/仰拍/贴地时空白穿帮；必须垂直四层都有内容。
4. 灯具实体与补光逻辑混写 → 换角度光影结构坍塌；双维度分开写。
5. 参考图当母版 → 搬运姿势/构图/光；或反过来「有图就不写尺度与场内关系」。
6. 抽象标签（金属感/高级感/赛博感）→ 改成光学行为（粗糙度/反射率/磨损/接触阴影）。
7. 空泛质量词：masterpiece / best quality / cinematic / epic / photorealistic / 写实 / 仿真人 → 删。
8. 写「红或蓝」给模型选择权 → 必须二选一。
9. 多角色共享参数不一致、每个变体各造一套锚点 → 换张脸。
10. 写「前中后景 0-3m/3-15m」当三维空间 → 这是二维构图，场景卡改用纹理随距离递减。

## 11. 禁止

- 不虚构资产编号、参考图、版本号、画幅；缺参考就写明缺失并标「待生成」，不写「已锁定」。
- 不把工程参数放进错的层（场景卡不写相机，定妆卡不写剧情光）。
- 不改用户原文占位符来「凑合法」；非法前缀先报告再由用户决定映射。
- 不静默放行门禁 FAIL；不删除历史版本。

## 12. 自检（交付前逐条打勾）

1. 编号/类型/唯一性合法，未用中文前缀新建？ 2. generate/reference 模式分清？ 3. 四类锚点齐全且唯一位置（无携带物时已写 `No carried props in this sheet` + 依据）？ 4. 参考图职责与不带入写清，尺度/场内关系补上？ 5. 场景卡零相机锁+四层+双维度+非对称+叙事置景？ 6. 分镜卡相机全锁+七要素？ 7. 道具五维+持握位+比例？ 8. DNA 签名已注入、Mandates 全覆盖、Forbidden 已并负向？ 9. 暗部/高光/接触阴影有交代？ 10. 门禁结果已记录（PASS/WARN/FAIL + 证据）？ 11. 提示词长度已核对（≤2000 字符、目标 250–320 词；未按「场景卡 400–500 词」等误记规则砍内容）？ 12. 超出主提示词的分析已放场景卡/设计文档（如 `构想/`），`PROMPT_MAIN` 只留可执行主提示词？ 13. 关键设定已注明来源、无设定外发明？ 14. 门禁方式已标注（linter 或「人工核对（非 linter 机械判定）」），无伪 PASS / 静默 FAIL？
