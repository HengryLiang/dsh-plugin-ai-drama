# 资产生产（Drama Asset）

> 定位：管资产**做得对不对、能不能复用、跨镜是不是同一套**。卡落在插件的资产库/草稿区，字段格式由插件定义；本技能只给制作判据与门禁。
> 不负责：分镜表结构与镜号（drama-storyboard）、单镜提示词写法（drama-seedance-prompt / drama-shot-prompt）、剧情台词（drama-script）。
> 版本：v0.7（2026-11-12）载具强制细节按**机动/非机动分流**：机动载具必含驾驶位仪表盘/中控，非机动载具必含操纵/乘坐位细节（桨/舵/鞍/把手/座板）；载具必须建 VEH 卡（§2）、走 §4.2；场景（§4.3）不变；角色、场景空间卡、分镜等其余类型的现有规则与门禁一行不改。

**生产顺序（七层推导，不跳）**：叙事需求（这资产为哪场服务）→ 资产设计（画什么/模式 A·B）→ 艺术指导（全局 DNA）→ 摄影与空间（分镜卡相机 / 场景卡空间几何）→ 光影物理（分镜卡光比 / 场景卡灯光蓝图）→ 渲染物理（材质光学/镜头签名）→ 模型优化（大气/纹理递减）。

## 1. 何时用

- 用户要建角色/场景/道具/载具卡、定妆照、场景概念图、资产参考图；
- 要给道具（PRP）出资产图（白/灰底 + 三视图 + 细节图，图版走 §4.1 独立分支）；
- 要给载具（VEH）出资产图（走 §4.2 独立分支，**必含驾驶位仪表盘（机动）或操纵/乘坐位（非机动）细节图**）；
- 要给场景（SPC）出**场景图**（走 §4.3 独立分支：**一张完整场景图**，按场景特性选平视/俯瞰/其他视角，不做细节小图）；
- 已有资产卡要审：一致性、可复用性、风格是否统一；
- 分镜提示词里的资产占位符解析不出，或镜头里出现了没建卡的资产；
- 需要按同一套风格基准统一一批资产。

### 1.1 信息来源与边界（硬口径）

- **允许只读引用**：项目内 `.aidrama/characters.json`、剧集契约、总纲、人物设定卡、本剧记忆、剧本/分镜；引用时注明来源（文件/区块/字段）。
- **禁止发明**：不得添加设定外的新角色、关系、道具、能力、时间线、服装/伤情等事实；未知就写「未提供/待补」，不得用常识补全。
- **冲突口径**：同一事实以最新来源为准；资产卡与文本冲突时以资产卡为准（已锁定卡优先），并标注差异与依据。
- **可追溯**：关键设定尽量逐条带来源；无来源的新增内容视为违规。
## 2. 编号与类型（硬口径）

- 10 类前缀，顺序固定：**CHR 角色 / SPC 场景 / PRP 道具 / SHT 分镜 / CST 服装 / VEH 载具 / EXP 表情 / SFX 特效 / VOX 配音 / MUS 音乐**。**载具必须建 VEH 卡**（分析层自 drama-asset-analysis v1.3 起输出 VEH）；不得把载具建成 PRP。
- 格式 `前缀 + 3–6 位序号`（CHR001 / CHR1000）；变体后缀 `_01–_99`（CHR001_02）合法；编号项目内全局唯一，不得重复分配。
- **数量不设上限**：资产卡与各类型数量不设业务上限；**不要以「某类型已满」为由拒绝建卡**；编号支持 3–6 位序号。
- 新建一律英文前缀三位编号；读取兼容中文旧前缀（角色01 ≡ CHR001），但**不得用中文前缀新建**。
- 非法前缀（EFF/EXT 等）**不静默改写**：标「未登记」，请用户确认映射，原文占位符不动。
- 外部模板里的类型按本插件归位：建筑→SPC（或作为场景内结构写进场景卡）、群演→CHR（群演级）、声音→VOX/MUS、特效→SFX；外部的 ARC/EXT/EFF/SND 前缀在本插件非法，不得新建。
- 引用统一 `{{Asset_<ID>_<字段>}}`，一个 ID 只指一个资产；资产卡里写清叙事功能与首次登场，方便复用检索。
- **资产索引接口**：开工前读索引（外部项目为 `00_Asset_Index.md`，插件内为资产库/卡表）的「待生成」清单与占位符映射，按清单建卡；剧本/分镜里新出现的元素标「待生成」；状态变更（待生成→已生成→已验收）回写索引，并与分镜提示词、资产卡三向同步。

## 3. 卡结构（每张 generate 卡必须长这样）

- 头部：`id / type / name / status(draft|active|retired) / version / variantOf / aliases / relations / prompts / history`。
- 正文固定锚点：`## PROMPT_MAIN`（可直接抽卡的主提示词）、`## PROMPT_SEEDANCE`（视频精简版，按需）、`## NEGATIVE`（负向排除；**生成提交时键名用 `PROMPT_NEGATIVE`**，见 §3.1）、`## SCORECARD`（六维评级+总分）、`## RENDER_VERIFY`（出图后回填）。
- 先分生产模式：`generate` 生产型走全部门禁；`reference` 登记型只登记参考图与注释，不硬造生成门禁。
- 不覆盖已有 active 卡：改版走新版本或草稿；历史版本保留，不删除。

### 3.1 提示词提交结构与长度（硬口径，v0.16.305+）

- **提交结构**：client 组装 `[PROMPT_MAIN]\n<主提示词>\n\n[PROMPT_NEGATIVE]\n<负向提示词>`，其余非空键按字母序 `[KEY]` 追加；单卡与批量同构；CRLF 统一归一；**不静默截断**。负向提示词必须存为 `PROMPT_NEGATIVE` 键（不是 `NEGATIVE`）。
- **长度口径**：整段上限 **8000 字符**（client + host 双层校验，按 `String.length`；≤8000 通过、>8000 拒绝 `invalid-args`「提示词过长（上限 8000 字符）」，不创建任务）；主提示词目标仍 **250–320 词**。
- **禁止误记规则**：不存在「场景卡 400–500 词」的硬性要求；也不存在 2000 字符的旧硬限。不得按口头词数要求删减必要信息、材质/灯光/空间分析或识别锚点。
- **内容分层**：超出主提示词所需的细节/论证/分析放到场景卡或设计文档（如 `构想/`）；`PROMPT_MAIN` 只保留生成可执行的主提示词，不放长篇分析；排除项进 `PROMPT_NEGATIVE`，不在正文里重复一遍。
- 压缩顺序：先保证信息完整可执行，再在不丢信息的前提下压到目标区间；不得为凑字数编造、重复或删掉硬锚点。


### 3.2 角色多状态（本版只新增）

- **每状态独立提示词**：存 `promptsByState[stateId]`（对象键 `PROMPT_MAIN` 等）；写回用 `drama_asset_save(action='savePrompts', id, stateId, prompts)`；不传 `stateId` 仍写默认 `card.prompts`。
- **状态图上传**：用 `media-upload` 的 `purpose:'asset'` + `assetId` + `stateId`；状态必须已存在（先在 asset-save 增加空状态，再上传）；不传 `stateId` 仍走旧根媒体。
- **状态维护**：用 `drama_asset_save(action='saveStates', id, addStates/renameStates/deleteStates/defaultStateId)`（至少一项）；新增只追加末尾；默认状态不可删、至少留 1 个、状态数 ≤20；删除仍被分镜引用的状态会拒绝并返回 references（先改绑再删）；状态 id 用英文/数字/_/-（1–40），显示名可中文 1–24。
- **提示词边界不放宽**：每状态提示词同样受 §3.1 结构/8000 口径约束；saveStates 冲突可重新读取最新卡后重试。
- **旧卡兼容**：无 `media.states` 的角色卡读取时派生「默认」状态，**不写盘**；根 `media.images/thumbnail` 是 active 状态镜像。
- 状态上限由宿主校验（≤20）；单状态图片 ≤6；空状态可先建后上传。

## 4. 资产分工（别串层）

| 卡 | 锁什么 | 不锁什么 | 复用性 |
|---|---|---|---|
| 角色定妆（模式 A） | 本体：脸/体型/服装/发型/识别锚点 | 表情/场景光/镜头/动作 | 极高 |
| 角色剧照（模式 B） | 表情/动作/场景光/构图 | 本体（继承定妆卡） | 低 |
| 场景空间卡 | 空间结构/材质/灯光系统/大气条件 | 机位/焦距/构图/主焦/EV/前中后景 | 极高 |
| 分镜头卡 | 100% 相机：焦段/光圈/高度/角度/朝向/距离/焦点/景深+构图 | 不重新定义空间/材质/全局灯光 | 低 |
| 道具/载具/建筑 | 结构/材质光学/持握位/比例 | 机位/构图 | 高 |

场景空间卡是「搭影棚」：换任何角度仍成立才算合格；分镜头卡是「摆机位」：在该场景卡之上只加「相机怎么看」。

> 分支归属（v0.4）：本行中的**建筑按场景卡处理**；**道具（PRP）走 §4.1 分支并过 §8.1 门禁**；**载具（VEH）走 §4.2 独立分支并过 §8.2 门禁（不并入道具分支，但画布/背景/比例原则参考道具）**；**场景（SPC）展示图走 §4.3 分支并过 §8.3 门禁（空间卡仍按原规则，不进入该分支）**——不改本表其余行，也不改本技能其它章节的既有规则。

### 4.1 道具资产图输出分支（PRP · PROPSHEET）

> 独立分支：只约束 `PRP` 道具的资产图；角色、场景（含建筑）、**载具（走 §4.2）**、分镜的规则与门禁一行不改。

**入口与边界**
- 触发：`type` 为 `PRP`，且本次要**出图或重出图**（generate 模式）。
- 不触发：**VEH 载具（走 §4.2 独立分支）**、SPC 场景/建筑（按场景卡处理）、角色、分镜；`reference` 登记卡只登记参考图，不生成、不进本分支。
- **类型纠偏**：若发现「载具被建成 PRP」（分析层 v1.3 之前的历史卡），先改类型/重建为 VEH 卡再按 §4.2 出图；不得按道具分支给载具出图。
- 旧卡：不强制返工；新分支只对新建卡与重出图生效（沿用 §3 版本纪律）。

**图版硬规格（逐条可勾）**
1. **背景**：默认中性灰 18%（`#808080`）无缝背景；白底（`#FFFFFF`）仅用于深色/单色道具或需抠图时，且必须在卡内写明选白底的理由。
2. **光**：平光，`key:fill ≤ 1:2`；无 rim、无环境光、无戏剧光、无投影方向；允许轻接触阴影。
3. **三视图**（正交、可量测）：刚性对称件＝正/侧/背；顶面密集件（面板/地图/握持面）＝正/侧/俯。三视图**同轴、同比例、共用基线、等高对齐**；显式禁 `perspective` / `3/4 view`（三视图不是三个透视摆拍）。
4. **细节图**：**张数按道具复杂度决定，不设固定数量**；必须覆盖该道具实际存在的特征——材质微距（掠射光）、机构/开合两态、刻字铭牌、持握/接触面、背面与内腔——存在即须有对应细节图，**不为凑数加无关细节**；格内看不清刻字/机构时，细节特写必须独立成图，不得硬塞进拼版。
5. **比例**：画面内标 cm 尺寸 + 1cm 网格尺 + 手部轮廓剪影；**禁真人、禁场景、禁环境道具**。
6. **画幅**：16:9 横版；三视图等高对齐，细节图独立条带或独立图。
7. **展示口径**：此图直接进资产库，必须无场景、无人物、无叙事语境（不带「为哪场服务」的剧情画面）。

**PROMPT_MAIN / PROMPT_NEGATIVE 骨架（整段 ≤8000 字符，v0.16.305+ 两段一起提交）**

```text
[PROMPT_MAIN]
[主体] 名称+类别+用途（中立描述，不写剧情/场景/人物）
[结构] 整体形态/比例/部件构成（可正交还原）
[材质] 五维光学行为（漫反射/镜面/透射/折射/光泽）
[版面] 16:9 单张：左侧正/侧/背（或正/侧/俯）三视图同基线等高；右侧细节图若干（按实际特征）
[背景光] 中性灰 #808080 无缝背景，平光 key:fill 1:2，无 rim/环境光/戏剧光
[尺度] cm 标注 + 1cm 网格尺 + 手部轮廓剪影（无真人）

[PROMPT_NEGATIVE]
无场景、无人物、无手部肖像、无透视摆拍、无戏剧光影、无景深虚化；plain seamless neutral gray #808080 backdrop, flat even lighting, no scene, no people, no hands, no room, no environment, no dramatic lighting, no depth of field, orthographic views
```

> 旧版客户端只提交主提示词时：把 NEGATIVE 段的最短排除句（`no scene, no people, plain #808080 backdrop`）并入主提示词末尾兜底；升级到 v0.16.305+ 后不再重复。

**衔接与豁免**
- 参考图职责：道具图只锁结构/材质/比例/持握位，不带入背景、棚拍光、机位、场景语境、人物（见 §5 新增行）。
- 风格 DNA：继承 `palette`/`texture`（含 Forbidden 色）；`lighting`/`composition` 的戏剧光影与构图策略**不注入**——复用角色模式 A 棚拍中性光豁免先例（§7），否则灰底图会被 Bible 的 1:8 光比与 rim 变成戏剧静物。
- 门禁：除 §8 原道具行外，另过 §8.1 分支门禁；RENDER_VERIFY 仍人工回填。

### 4.2 载具资产图输出分支（VEH · VEHICLESHEET）

> 独立分支：**载具不并入道具分支**（§4.1 只服务 PRP）；本分支参考道具分支的画布/背景/光/比例原则，但按载具特性另立规格。**先判动力类型，再定强制细节**：机动载具（汽车/摩托/机动船/飞机/工程车等）→ 驾驶位仪表盘/中控**必含**；非机动载具（手摇船/自行车/马车/人力车等）→ 操纵位/乘坐位细节（桨/舵/鞍/把手/座板/脚踏）**必含**，仪表盘不适用。

**入口与边界**
- 触发：`type` 为 `VEH`，且本次要**出图或重出图**（generate 模式）。
- 不触发：PRP（走 §4.1）、SPC 场景/建筑（按场景卡处理）、角色、分镜；`reference` 登记卡只登记参考图，不生成、不进本分支。
- 旧卡：不强制返工；本分支只对新建卡与重出图生效（沿用 §3 版本纪律）。

**图版硬规格（逐条可勾）**
1. **背景**：默认中性灰 18%（`#808080`）无缝背景；白底（`#FFFFFF`）仅用于深色/单色载具或需抠图时，且必须在卡内写明选白底的理由。
2. **光**：平光，`key:fill ≤ 1:2`；无 rim、无环境光、无戏剧光、无投影方向；允许轻接触阴影。
3. **外观三视图**（正交、可量测）：正/侧/背；顶部特征多（越野/改装/舱盖结构）时用正/侧/俯。三视图**同轴、同比例、共用基线、等高对齐**；显式禁 `perspective` / `3/4 view`。
4. **必含：驾驶/操纵位细节图（强制，缺失即 FAIL，按动力类型二选一）**：
   - **机动载具**（汽车/摩托/机动船/飞机/工程车等）：能看清驾驶位视角的**仪表盘与中控**——仪表刻度/屏幕、方向盘、中控按键/挡杆布局；取正对驾驶位或 3/4 驾驶位角度。
   - **非机动载具**（手摇船/自行车/马车/人力车等）：能看清**操纵位/乘坐位**——桨/舵/鞍/把手/座板/脚踏的持握与安装关系；**不得以「没有仪表盘」为由不提供该细节**。
   - 允许与外景三视图同张拼版，但**清晰可辨是底线**；拼版看不清即必须独立成图。**为什么**：载具是动作戏的「第二主角」，驾驶/操纵细节决定车内/船上镜头的可拍性与观众代入；缺了它，载具卡视同未完成。
5. **其余细节图**：按该载具实际存在的特征覆盖——车灯/轮毂/车牌位置/门把手/座椅材质/后视镜/充电口或加油口等；存在即须有对应细节图，不设固定张数、不为凑数加无关细节。
6. **比例**：按真实量级标 cm/m 尺寸 + 1cm/1m 网格尺 + 轮廓剪影；**禁真人、禁场景、禁环境道具**。
7. **画幅**：16:9 横版；外观三视图等高对齐，仪表盘与细节图独立条带或独立图。
8. **展示口径**：此图直接进资产库，必须无场景、无人物、无叙事语境。

**PROMPT_MAIN / PROMPT_NEGATIVE 骨架（整段 ≤8000 字符，v0.16.305+ 两段一起提交）**

```text
[PROMPT_MAIN]
[主体] 载具名称+类别+用途（中立描述，不写剧情/场景/人物）
[结构] 整体形态/长宽高比例/车身与部件构成（可正交还原）
[材质] 五维光学行为（车漆漫反射/玻璃镜面/轮胎哑光/金属件/光源）

[PROMPT_NEGATIVE]
无场景、无人物、无手部肖像、无透视摆拍、无戏剧光影、无景深虚化；plain seamless neutral gray #808080 backdrop, flat even lighting, no scene, no people, no hands, no room, no environment, no dramatic lighting, no depth of field, orthographic views
```

> 旧版客户端只提交主提示词时：把 NEGATIVE 段的最短排除句并入主提示词末尾兜底；升级到 v0.16.305+ 后不再重复。

**衔接与豁免**
- 参考图职责：载具图只锁外廓结构/材质/比例，**以及驾驶位仪表盘与中控布局**；不带入背景、棚拍光、机位、场景语境、人物（见 §5 新增行）。
- 风格 DNA：同 §4.1——继承 `palette`/`texture`（含 Forbidden 色），`lighting`/`composition` 的戏剧光影与构图策略不注入（复用角色模式 A 棚拍中性光豁免先例，§7）。
- 门禁：另过 §8.2 载具分支门禁；RENDER_VERIFY 仍人工回填。

### 4.3 场景资产展示图分支（SPC · SCENEVIEW）

> 独立分支：场景资产只产出**一张完整场景图**（不是多视图技术图版、不做细节小图）；唯一需要决策的是**视角**——按场景特性选俯瞰/平视/其他。与「场景空间卡」分开：**空间卡仍按 §4/§8 原规则（零相机锁）**，本分支只定义展示图。

**入口与边界**
- 触发：`type` 为 `SPC`，且本次要**出/重出场景图**（generate 模式）。
- 不触发：场景空间卡生成（走原规则）、角色、道具、载具、分镜；`reference` 登记卡只登记参考图。
- 旧卡：不强制返工；本分支只对新建卡与重出图生效。

**视角判定（按场景特性选一个，整张图统一用该视角）**

| 场景特性 | 视角 | 要求 |
|---|---|---|
| 室内封闭空间（卧室/病房/办公室/审讯室/车厢内部等） | **平视** | 人眼高度、自然透视；完整呈现四壁/家具/门窗与空间关系（参照 SPC013 图） |
| 走廊/长条空间/街道/巷子/外立面 | **平视** | 沿纵深或正对立面，完整呈现，不裁切关键空间 |
| 需要交代整体布局/动线/多空间关系（别墅/大型室内/建筑群） | **俯瞰** | 高位俯视或顶视，看清房间划分/动线/边界 |
| 多层/复杂结构（楼梯/挑高/仓库/地下室） | **俯瞰** 或 **其他（斜俯/轴测，按可读性选）** | 一图说清层次关系 |
| 开阔外景（广场/山地/田野/江岸） | **平视** 或 **俯瞰** | 按叙事重点选 |
| 拿不准 | **平视** | 最接近成片视角，默认 |

**图版硬规格（逐条可勾）**
1. **单张完整场景**：16:9 单图；**不拼版、不加细节小图/特写格、不加标注/箭头/比例尺/文字标签**——场景要看的是一眼能读懂的「完整环境」。
2. **一图一视角**：只选一个视角；必须能看全场景主要空间关系，不裁掉关键区域。
3. **允许自然透视**：场景图就是拍摄视角，**不写焦段/光圈/景深/运镜等镜头参数**（那是分镜卡职责）。
4. **无人物、无剧情动作**；场景本体即背景，**不用灰底/棚拍**（与道具/载具不同）。
5. **材质/光影/色板继承 DNA**（palette/texture/lighting/composition）——场景光影与色板属于场景语义，不剥离。
6. **与空间卡分离**：本图的任何相机/构图参数**不得写入空间卡**；空间卡继续零相机锁。

**PROMPT_MAIN / PROMPT_NEGATIVE 骨架（沿用 §3.1 两段结构，整段 ≤8000 字符）**

```text
[PROMPT_MAIN]
[主体] 场景名+类型+功能（中立描述）
[视角] 选定视角（平视/俯瞰/其他）+ 一句视角说明
[完整场景] 空间全貌：四壁/家具/门窗/入口/纵深/关键置景（写全，不写局部特写）
[材质光影] 五维材质 + 环境光方向与色温
[排除] 无人物、无剧情动作、无细节小图、无标注文字

[PROMPT_NEGATIVE]
无人物、无剧情动作、无细节小图、无标注/箭头/比例尺/文字；no people, no characters, no scene action, no detail callouts, no annotations, no arrows, no scale bars, no text, no labels, no split panels, no collage, no floor plan, no elevation insets
```

**衔接与豁免**
- 平台若提供「场景展示图入口」（`PROMPT_SCENESHEET`）：其内容与本节**单张完整场景**提示词一致——**不是多视图拼版/细节图版**；入口文案/校验若仍写「正交/标注」需同步改为「完整场景 + 视角」。
- 参考图：场景图只锁空间布局/材质/光位，不带入细节小图、标注、人物与镜头参数。
- 门禁：另过 §8.3 场景分支门禁；RENDER_VERIFY 仍人工回填。

|---|---|---|
| 人物图 | 身份/面部/发型/年龄/体型/固有造型 | 它的姿势、机位、光、背景 |
| 服装图 | 服装结构、材质、配件 | 模特姿势与体型 |
| 场景图 | 空间结构、天气、时间、色调、材质 | 它的机位与构图 |
| 特效图 | 能量颜色、形态、密度、尺度 | 它所在的场景 |
| 关键帧 | 用户指定的机位、姿态、透视、构图 | 未指定的部分 |
| 参考视频 | 动作连续性、上镜末帧、站位、速度、节奏 | 不当时装/场景母版 |

## 6. 一致性锚点（跨镜同一资产）

- 角色模式 A：识别锚点 **≥3**（位置+光学行为，如「左眉上 2cm 旧疤，逆光时比周围皮肤亮」）、面部结构点 **≥6**、身体语言点 **≥3**、随身物品落到**唯一位置**（哪只手哪根手指/挂腰带哪侧）；**若设定/资产卡确实没有携带物，允许写 `No carried props in this sheet` 并注明依据（来源），判 PASS；不得编造携带物**。
- 多角色同场：同一条可见参数（身高差/服装色/伤势）在各卡中**一字不差**；冲突以「能对上分镜的那一版」为准并回改其余卡。
- 变体（觉醒/战斗/服装/破损）：沿用同一 `asset_id` 与同一组识别锚点，只写增量差异；标 `variantOf` + 覆盖维度；编号或变体变更后，索引/分镜提示词/资产卡三处同步。

## 7. 风格 DNA 对接

**视觉圣经前置（强制）**：开工前调用 `drama_get_project` 读 `styleDNA`/`styleDirection`/`stylePrompt`；`stylePrompt` 存在（已冻结）时以其五维为硬约束，资产 Prompt 必须服从并保留只读「视觉风格基准」章节；未冻结先提示用户用视觉圣经技能建/锁，再开工；不得私自改色板/光比/材质/构图/运镜。扩展圣经见 `构想/视觉圣经/<项目>.md`。

- 优先级链：用户明确指令 > 风格圣经 Mandates > 12 维 DNA > 软偏好 > 手写 DNA > 默认值。Bible 是风格单一事实源，**禁止在下游 Prompt 私自改色板/光比/磨损度**。
- 每个 Prompt 注入约 80–100 词 DNA 签名：摄影机/镜头/胶片/色板(HEX)/LUT/光比/磨损度/构图哲学/颗粒。
- 12 维落实位置：Color/Lighting→灯光色温；Material→材质光学；Lens→镜头焦段；Composition→构图；Shape/Pattern→体块与纹样；Architecture→空间与垂直层次；Costume→服装；Prop→道具；Motion→大气与运动；Emotion→情绪光效。
- Mandates 逐条覆盖 100%，Forbidden 全部并入负向词；用户指令偏离 Mandates 时必须提醒确认。
- 场景卡**永远不注入相机参数**（Bible 的焦段/构图策略只进分镜卡）；角色模式 A 是棚拍中性光身份证，Bible 的戏剧光影不得覆盖它。
- **道具/载具分支（§4.1 / §4.2）**：继承 `palette`/`texture`（含 Forbidden 色），但 `lighting`/`composition` 的戏剧光影与构图策略不注入——同角色模式 A 的棚拍中性光豁免；否则 `#808080` 灰底会被 Bible 的 1:8 光比与 rim 覆盖，道具图变成戏剧静物。
- **场景展示图分支（§4.3）**：**不豁免**——继承 `palette`/`texture`/`lighting`/`composition`；场景的光影与构图就是场景语义的一部分，只去掉镜头语言（焦段/景深/运镜）与人物。

| 检查项 | PASS 判据 |
|---|---|
| 视角判定 | 与场景特性匹配（室内封闭/走廊街道→平视；需交代整体布局→俯瞰；多层复杂→俯瞰或斜俯/轴测；开阔外景→平视或俯瞰；拿不准→平视） |
| 完整性 | **单张完整场景**，能一眼读懂主要空间关系；关键空间不被裁掉 |
| 无细节小图 | **无特写格/拼版/细节小图**；无标注、箭头、比例尺、文字标签 |
| 人物/叙事 | 无人物、无剧情动作 |
| 镜头参数 | 不写焦段/光圈/景深/运镜（允许自然透视，但显式不锁镜头参数） |
| DNA | `palette`/`texture`/`lighting`/`composition` 已继承（场景分支不豁免）；Forbidden 未出现 |
| 空间卡隔离 | **未向场景空间卡写入任何相机/构图参数**；空间卡仍零相机锁；场景图只进资产库与审美确认 |
| 旧卡 | 未强制返工；本分支只对新卡与重出图生效 |

任一 FAIL：重写一次 → 仍 FAIL 标人工（status=需重做），不静默放行；RENDER_VERIFY 仍人工回填。本分支**不改变**场景空间卡规则、角色 A 与分镜行。

## 9. 其余资产类型的要点

- 群演（CHR 群演级）：外形/数量/站位规则/不抢焦；用母版复用保证群体一致，只写位置/数量/服装色块，不给每个群演分面部戏。
- 特效（SFX）：自发光与光学行为、形态/密度/尺度、运动与状态机、对环境的照亮影响、与资产风格对齐。
- 配音（VOX）/音乐（MUS）：音色/语速/节奏/情绪/挂钩角色；卡里存音频引用与用途，不写生成提示词。
- 服装（CST）/表情（EXP）：默认作为角色卡的变体或字段存在；确需独立成卡时沿用同一组识别锚点，只写增量。
- 道具（PRP）：资产图走 §4.1 分支、过 §8.1 门禁。
- 载具（VEH）：资产图走 **§4.2 独立分支**（不并入道具）、过 §8.2 门禁，**必含驾驶/操纵位细节（机动=仪表盘/中控；非机动=桨/舵/鞍/把手/座板）**；建筑按场景卡处理。
- 场景（SPC）：**场景图**走 §4.3 分支、过 §8.3 门禁（**一张完整场景图**，按场景特性选平视/俯瞰/其他；不做细节小图与标注）；**场景空间卡仍按原规则**（零相机锁），两者不混。

## 10. 常见翻车（看到就改）

1. 场景卡锁机位/构图 → 只能生成一个角度，复用性归零。
2. 主 Prompt 残留 mm/f 值 → 与分镜叠加指令冲突，模型倾向听主 Prompt。
3. 只写地面+墙面 → 俯拍/仰拍/贴地时空白穿帮；必须垂直四层都有内容。
4. 灯具实体与补光逻辑混写 → 换角度光影结构坍塌；双维度分开写。
5. 参考图当母版 → 搬运姿势/构图/光；或反过来「有图就不写尺度与场内关系」。
6. 抽象标签（金属感/高级感/赛博感）→ 改成光学行为（粗糙度/反射率/磨损/接触阴影）。
7. 空泛质量词：masterpiece / best quality / cinematic / epic / photorealistic / 写实 / 仿真人 → 删。
8. 写「红或蓝」给模型选择权 → 必须二选一。
9. 多角色共享参数不一致、每个变体各造一套锚点 → 换张脸。
10. 写「前中后景 0-3m/3-15m」当三维空间 → 这是二维构图，场景卡改用纹理随距离递减。

## 11. 禁止

- 不虚构资产编号、参考图、版本号、画幅；缺参考就写明缺失并标「待生成」，不写「已锁定」。
- 不把工程参数放进错的层（场景卡不写相机，定妆卡不写剧情光）。
- 不改用户原文占位符来「凑合法」；非法前缀先报告再由用户决定映射。
- 不静默放行门禁 FAIL；不删除历史版本。
