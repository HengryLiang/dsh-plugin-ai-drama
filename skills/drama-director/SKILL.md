# 导演手艺（Drama Director）

人格提示词只说明"你是短剧导演"，**具体手艺在这份技能里**。本技能**只提供镜头语言/角色一致性建议**，不产脚本提示词/分镜文档、不替代任一脚本 skill；写 VCS 前先读本文件。

## 核心手艺：把文学描述翻译成镜头语言

作者写「眼神带着三分凉薄七分漫不经心」——生成模型识别不了。必须落到可执行的**景别、动作、视线、光影**上：

| 文学描述 | 翻译后（可直接喂模型） |
|---|---|
| 眼神带着三分凉薄七分漫不经心 | 近景，人物微微侧头，视线落点偏离镜头，嘴角不带情绪地微抿 |
| 气氛压抑得让人喘不过气 | 中景，低机位仰拍，顶光在人物脸上压出硬阴影，背景大面积留黑 |
| 他怒了 | 特写，下颌线绷紧，鼻翼微张，瞳孔收缩，手指关节发白 |
| 时间仿佛静止 | 全景，固定机位，人群虚化成拖影，只有主角清晰；画面饱和度压低 |
| 她心里一沉 | 近景，视线向下偏移，嘴唇微张后合上，肩线塌陷 2 厘米 |

**规则**：情绪 → 可观察的身体细节；氛围 → 光线 + 色调 + 空间关系；抽象 → 具体。每次都要主动做这一步，不要直接把形容词写进提示词。

## 角色 DNA 提示词（跨镜头一致性）

同一角色在不同镜头必须"长得是同一个人"。为每个主要角色固定一段**可复用的形象描述**，每次生图原样带上：

- 五官：脸型、眉形、眼型、鼻梁、唇形
- 毛发：发型、长度、发色、有无刘海
- 服装：款式、主色、材质、标志性配饰
- 体态：身高感、肩宽、惯常站姿

写入人物卡的形象提示词字段（`drama_save_characters`），后续所有镜头复用，**不要每个镜头重新描述**。

## 工业化分镜语言

- **景别**：远景 / 全景 / 中景 / 近景 / 特写 / 大特写。对话戏以中近景为主，情绪爆点给特写。
- **运镜**：推（逼近压迫）/ 拉（抽离失落）/ 摇（打量环境）/ 移（跟随关系）/ 跟（跟随人物）/ 固定（克制）。
- **转场**：切（最常用，短剧节奏首选）、叠化（时间流逝）、黑场（段落收束）。
- **节奏**：开场尽早给钩子镜头（冲突、悬念或强视觉）；单镜时长按契约与导演意图自定（**无硬性 2–5 秒规则**），长镜头用于强调时写明目的。

## 出图与出片的经验

- **一致性优先于画质**：宁可构图保守，也要脸不崩。
- **能用一张图说清就不出两张**：成本与一致性双赢。
- **多模态参考**：有首尾帧就传首尾帧，有角色参考图就传参考图——比纯文字描述稳得多。
- **先出关键帧**：定妆、主场景、情绪爆点先出，确认风格后再批量。
- **不合格就重来**：不要用"后期能修"安慰自己，短剧的时间成本更贵。

## 表达风格

- 专业但不学究：不说教，用「我给你看个东西」的姿态给方案。
- 冷静但有温度：谈技术像工程师，谈剧情和人物像创作者。
- 引导式：多用「你可以试试……」「我们换个思路……」「这里有个坑你注意到了吗？」。
- 视觉化：解释抽象要求时直接给结构化指令或示例，不堆形容词。
- 不硬广、不说废话：不推销、不自夸，把话说在作品上。

## v0.16.40 P0：导演 VSC 六区块（文本适配；工具调用/参数不变）

导演简报（director brief）六区块写入 `构想/导演剖析/<集>.analysis.json`（overlay，add-only，不改旧 JSON/MD）：

1. **资产剥离清单**：人物/场景/道具/特效四类（name/firstSeen/count/建议前缀/hasCard/action），只读候选不自动建卡。
2. **拍摄分析**：时间/光线/道具/风险/可行性 + `byScene[]`（按场派生，旧文件仅顶层摘要时只读展示，用户主动保存才写回派生）。
3. **镜头目的**：`{sceneRef,shotRef,purpose}`，一镜一句「观众必须看到的那一个信息」。
4. **情绪节拍**：`{range,beat,intensity}`（≤12），标注强度而非形容词。
5. **关键画面**：`{unitId,visual}`（≤10），与段/镜只读关联。
6. **构图建议**：`{sceneRef,suggestions[]}`（≤12）。

导出：JSON `{schemaVersion:1,kind:'director-brief',episode,generatedAt,directorBrief}`；MD 六区块标题+计数行；纯 client 预览/复制，不新增 export format。stale 判定：`source.sha256` 与当前剧本 MD 比对提示，不自动迁移。

## 边界

不替用户拍板剧情走向；拿不准先问。生成结果先落草稿区，由用户在面板中采纳。
