# 短剧立项（Drama Setup）

立项的产出是**剧集契约**——它是后面大纲、剧本、分镜全部生成的强约束输入。契约糊，后面全糊。

## 步骤

1. `drama_create_project` 建项目（**仅在用户明确表达建项意图并确认后执行**；已存在则跳过）。
2. 向用户确认四项关键信息：**投放平台**、**单集时长**、**目标集数**、**审核红线**。
   用户没说时，按平台惯例先给建议值再请其确认，不要空着。
3. `drama_save_contract` 写入契约。
4. `drama_get_project` 复核，把契约读回来念给用户确认。
5. （可选，不强制）新项目可顺带建议填 3 项核心世界设定：`soulDeath`（死亡权重）、`powerSystem`（战力天花板）、`worldSpace`（舞台/通行成本）；其余 5 项可后补；旧项目只提示「可补」，不得强制。

## 平台惯例参考（先建议、后确认，不要当默认事实）

| 平台 | 单集时长 | 画幅 | 常见集数 |
|---|---|---|---|
| 抖音 / 快手 | 60~120 秒 | 竖屏 | 60~100 |
| 红果 / 小程序剧 | 90~180 秒 | 竖屏 | 80~120 |
| 横屏精品短剧 | 180~600 秒 | 横屏 | 20~40 |

钩子密度建议写成可检验的口径，例如「每 30 秒一个钩子，每集结尾必须有悬念」，不要写「节奏快」这种没法验收的话。

## 禁止

- 不要在契约缺字段的情况下就开始写大纲——先用 `drama_check_consistency` 看缺口。
- 不要把用户的临时口述当最终契约，必须回读确认。
- **无明确建项意图时不得自动立项**：用户未明确表达建项意图（建立项目 / 创建新项目 / 新建短剧 / 开个新短剧 / 立项 / 我想做一部短剧 / 新项目等）时，不得主动加载立项指引、不得主动追问平台 / 单集时长 / 目标集数、不得调用 `drama_create_project`。
- **已有项目但无有效契约**：只提示「可补契约」（先用 `drama_get_project` / `drama_check_consistency` 展示缺口），不得自动新建项目或另立新项；新建须用户明确确认。

## 写入稳健性（大参数/长文本，2026-10-20 补充）

- **大对象优先拆批**：契约、世界观、人物数组一次只写一个对象/一批（人物建议 ≤10 条），不要和其他大参数**并行**提交。
- **长文本用单字符串 + `\n` 转义**；不要手写多层嵌套 JSON 字符串。
- 文本内用中文引号「」，避免 ASCII 双引号带来的 JSON 转义风险。
- 若模型层报 `tool input is invalid JSON`：先 `drama_get_project` / `drama_get_progress` 判断是否已落盘（再看 `.aidrama/audit/audit.jsonl`），未落盘再拆小重发。
- 若报 `value.result must be an object`：那是宿主输出校验误报（v0.15.8 已修），数据通常**已落盘**，不要重复采纳。
