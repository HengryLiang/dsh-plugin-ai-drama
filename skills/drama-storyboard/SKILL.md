# 分镜表（Drama Storyboard）

## 前置

`drama_read_episode` 取该集剧本；`drama_get_project` 取人物卡的**形象提示词锚点**。

## 每个镜头八列

| 列 | 要求 |
|---|---|
| 镜号 | `集-序`，如 `1-1`、`1-2`；集内连续，不重复 |
| 景别 | 远景 / 全景 / 中景 / 近景 / 特写 / 大特写 |
| 运镜 | 推 / 拉 / 摇 / 移 / 跟 / 固定；一镜一动，不堆砌 |
| 画面描述 | 只写镜头里看得见的 |
| 台词 | 该镜头内的对白或旁白，可空 |
| 音效 | BGM / 环境音 / 拟音 |
| 时长 | 秒，一镜 2~5 秒 |
| 提示词 | 生图提示词：**复用人物卡的形象锚点**＋本镜画面＋景别＋光线氛围 |

## 节奏纪律（竖屏短剧）

1. 开场 3 秒内必须是特写或强冲突镜头。
2. 平均每 3~5 秒切一次镜；不要有超过 8 秒的长镜。
3. 全集合计时长必须落在契约的单集时长区间内。

## 交付

`drama_save_draft`（`kind: "storyboard"`，`order` 为集数，`content` 为镜头数组的 JSON 字符串）写入草稿区，
然后 `drama_check_consistency` 自检（重点看镜号重复与时长越界）。

## 写入稳健性（2026-10-20 补充）

- 镜头数组大时**分批提交**（每批建议 ≤10 镜），不要与人物/大纲等其他大参数并行写入。
- 采纳分镜草稿成功后若宿主报 `value.result must be an object`，那是输出校验误报（v0.15.8 已修），数据已落盘，**不要重复采纳**。
- 模型层报 `tool input is invalid JSON` 时先查审计/进度判断是否已落盘，未落盘再拆小重发。
